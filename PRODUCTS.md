# ReWear Product Creation Guide (`PRODUCTS.md`)

This guide explains step-by-step how to add, validate, and manage products in ReWear using the automated Product Pipeline and Factory tool (`npm run new-product`).

---

## 1. Overview & Architecture

ReWear uses a unified **Garment Specification (`GarmentSpec`)** format that supports both rectangular panel goods (totes, pouches, cushion covers, slips) and curved CAD garments (raglan tees, tops, bodices).

### Key Architectural Concepts
1. **Product Registries**:
   - `CORE_PRODUCT_TEMPLATES` in [`src/engine/templates.js`](file:///c:/Users/vinay/Documents/antigravity/happy-volta/src/engine/templates.js): The built-in core products (`tote_bag`, `pouch`, `cushion_cover`, `kids_frock`, `child_top`).
   - `CUSTOM_PRODUCT_TEMPLATES` in [`src/engine/customRegistry.js`](file:///c:/Users/vinay/Documents/antigravity/happy-volta/src/engine/customRegistry.js): Dynamically added products generated by `npm run new-product`.
   - `PRODUCT_TEMPLATES` exports `{ ...CORE_PRODUCT_TEMPLATES, ...CUSTOM_PRODUCT_TEMPLATES }` so that engine matching, sizing, 2D previews, and tailor blueprints automatically discover all products.

2. **Multilingual Localization**:
   - Every product, size, and pattern piece requires translated names in **English (`en`)**, **Hindi (`hi`)**, and **Telugu (`te`)**.
   - Custom translations are automatically maintained in [`src/i18n/customTranslations.js`](file:///c:/Users/vinay/Documents/antigravity/happy-volta/src/i18n/customTranslations.js) and merged into [`src/i18n/translations.js`](file:///c:/Users/vinay/Documents/antigravity/happy-volta/src/i18n/translations.js).

3. **Automated Verification Pipeline**:
   - `npm run check-products` runs [`src/engine/productValidator.js`](file:///c:/Users/vinay/Documents/antigravity/happy-volta/src/engine/productValidator.js) to verify all products across 7 checks:
     1. Stated piece areas match geometry ($W \times H$)
     2. No overlapping cut pieces on standard cutting sheet
     3. Cut pieces fit within sheet boundaries including seam allowances
     4. `plain_base` pieces use zero scraps and have role `base`
     5. Hybrid rules (balanced plain base + scrap accents, mirrored pair symmetry)
     6. Translation keys present in `en`, `hi`, and `te`
     7. Honesty check (`tailorVerified: false`, no unverified claims)

4. **Generic Renderers**:
   - **Generic Flat Preview** ([`src/utils/product2DLayout.js`](file:///c:/Users/vinay/Documents/antigravity/happy-volta/src/utils/product2DLayout.js)): Automatically arranges pattern pieces in neat shelves with clipping paths so patchwork renders directly inside each piece's outline.
   - **Generic Blueprint** ([`src/utils/tailorBlueprintData.js`](file:///c:/Users/vinay/Documents/antigravity/happy-volta/src/utils/tailorBlueprintData.js)): Automatically generates tailor cutting dimensions, materials lists, and 6-step stitching sequences routed by the product's `construction` category.

## 2. Step-by-Step Guide: Adding a Product

```json
      "names": {
        "en": "Standard (Adult)",
        "hi": "मानक (वयस्क)",

          "height": 70,

          "fabricSource": "either"
        }
      ]
    }
  }

```

### Step 2: Run the Factory Script
Run `npm run new-product` pointing to your config file:
```bash
npm run new-product -- --config products/utility_apron.json
```

The script will:
1. Parse your JSON configuration.
2. Calculate exact seam allowances ($W + 2 \times \text{SA}$, $H + 2 \times \text{SA}$) and piece areas.
3. Apply grain line rules and source constraints (`plain` $\rightarrow$ `plain_base`, `scrap`/`either` $\rightarrow$ `scrap`).
4. Attach tailor disclaimers (`tailorVerified: false`, `disclaimer: TAILOR_DISCLAIMER`).
5. Run `validateProductSpec()` to guarantee the spec passes all 7 validation checks.
6. Write the registered spec into `src/engine/customRegistry.js`.
7. Write multilingual translations (`en`, `hi`, `te`) into `src/i18n/customTranslations.js`.

### Step 3: Verify the Product Pipeline
Run the product check tool to verify your new product alongside all existing products:
```bash
npm run check-products
```
Expected output:
```text
✓ tote_bag: 3 sizes, 1 variant, all checks passed
✓ pouch: 3 sizes, 1 variant, all checks passed
✓ cushion_cover: 3 sizes, 2 variants, all checks passed
✓ kids_frock: 4 sizes, 1 variant, all checks passed
✓ child_top: 2 sizes, 3 variants, all checks passed
✓ utility_apron: 1 size, 2 variants, all checks passed
```

Run the entire test suite:
```bash
npm test
```

## 3. Configuration File Schema Reference

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `id` | `string` | **Yes** | Unique snake_case identifier (e.g. `utility_apron`, `market_shopper`). |
| `names` | `object` | **Yes** | Multilingual names: `{ en: "...", hi: "...", te: "..." }`. |
| `category` | `string` | **Yes** | Product category: `'bags'`, `'home'`, `'clothing'`, `'garments'`, `'accessories'`. |
| `construction` | `string` | **Yes** | Construction archetype: `'tee'`, `'skirt'`, `'trousers'`, `'bag'`, `'cushion'`, `'pouch'`, `'flat'` (hemmed flat goods like aprons, placemats), `'casing'` (tubes/channels like scrunchies, drawstring pouches). |
| `description` | `string` | No | Short product description. |
| `sizes` | `object` | **Yes** | Map of size keys (e.g. `small`, `standard`, `chest56`). |
| `sizes.<key>.label` | `string` | **Yes** | Human-readable size label (e.g. `"Standard (Adult)"`). |
| `sizes.<key>.names` | `object` | No | Multilingual size labels: `{ en: "...", hi: "...", te: "..." }`. |
| `sizes.<key>.finishedDimensions` | `object` | **Yes** | Overall finished garment dimensions: `{ widthCm: number, heightCm: number }`. |
| `sizes.<key>.pieces` | `array` | **Yes** | List of pattern pieces (see Piece Schema below). |
| `materials` | `array` | No | List of notions and fabric requirements (e.g. thread, zipper, webbing). |
| `patternLibrary` | `object` | No | CAD pattern generator reference (see Pattern Library section below). |

### Piece Schema (`sizes.<key>.pieces[]`)

| Field | Type | Required | Description |
| :--- | :--- | :--- | :--- |
| `id` | `string` | **Yes** | Unique piece ID (e.g. `body_front`, `pocket`, `sleeve`). |
| `names` | `object` | No | Multilingual piece names: `{ en: "...", hi: "...", te: "..." }`. |
| `role` | `string` | **Yes** | 60-30-10 role: `'base'`, `'supporting'`, or `'accent'`. |
| `width` | `number` | **Yes** | Finished width in centimeters. |
| `height` | `number` | **Yes** | Finished height in centimeters. |
| `qty` | `number` | No | Number of pieces to cut (default: `1`). |
| `fabricSource` | `string` | **Yes** | Sourcing option: `'scrap'`, `'plain'`, or `'either'`. |
| `seamAllowanceCm` | `number` | No | Seam allowance on edges in cm (default: `1.0`). |
| `grainLine` | `string` | No | Orientation: `'lengthwise'` (warp $\updownarrow$) or `'crosswise'` (weft $\leftrightarrow$). |

#### Fabric Sourcing Options:
- `"scrap"`: Piece is cut from upcycled scraps (`fabricSource: 'scrap'`, `scrapEligible: true`).
- `"plain"`: Piece is cut from continuous solid yardage (`fabricSource: 'plain_base'`, `scrapEligible: false`). Must have role `'base'`.
- `"either"`: Piece can be pieced from scraps or cut from solid fabric (`fabricSource: 'scrap'`, `scrapEligible: true`).

## 4. Pattern-Library Garments (FreeSewing CAD Integration)

For garments requiring curved anthropometric CAD patterns (such as raglan shirts, bodices, and sleeves), the factory script integrates directly with pinned CAD datasets.

### Using FreeSewing Brian CAD:
Specify `"patternLibrary"` in your config:
```json
{
  "id": "child_raglan_top",
  "names": {
    "en": "Child Raglan Top",
    "hi": "बच्चों का रैगलान टॉप",
    "te": "పిల్లల రాగ్లాన్ టాప్"
  },
  "category": "garments",
  "construction": "tee",
  "patternLibrary": {
    "design": "brian",
    "version": "4.10.2"
  },
  "sizes": {
    "chest56": {
      "label": "Child Chest 56 cm (~3-4 Years)"
    },
    "chest62": {
      "label": "Child Chest 62 cm (~5-6 Years)"
    }
  }
}
```

When `patternLibrary.design` is `"brian"`, the factory script:
1. Loads the pre-generated mathematical dataset from [`src/engine/childTopBrianData.js`](file:///c:/Users/vinay/Documents/antigravity/happy-volta/src/engine/childTopBrianData.js).
2. Generates exact curved SVG `seamPath` and `saPath` definitions.
3. Embeds cut-on-fold specifications and vertical grain line markers.
4. Preserves accurate Shoelace polygon areas ($A = \frac{1}{2}\sum (x_i y_{i+1} - x_{i+1} y_i)$).
5. Enforces pinned FreeSewing version `4.10.2` provenance with **zero hand typing**.

## 5. Removing a Custom Product

To remove an auto-generated product from the registry:
```bash
npm run remove-product -- <productId>
```

Example:
```bash
npm run remove-product -- utility_apron
```

This will:
1. Delete the product entry from `src/engine/customRegistry.js`.
2. Clean up associated multilingual strings in `src/i18n/customTranslations.js`.
3. Keep core product templates completely untouched.

## 6. Tailor Verification & Honesty Rules

- All auto-generated products are registered with `tailorVerified: false` and `verifiedByTailor: false`.
- The product template includes the standardized disclaimer:
  > *"All pattern measurements are rectangle-based approximations for scrap cutting and must be verified by a professional tailor before final cutting."*
- Unverified marketing claims (e.g. `"tailor-verified"`, `"tailor-approved"`, `"verified pattern"`) are strictly forbidden by `productValidator.js` and will cause the validator to reject the specification.
- Only when an authorized master tailor has physically cut, stitched, and verified the garment may `tailorVerified` be marked `true`.
